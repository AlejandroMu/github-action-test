Módulo 1 · Automatización

Shell Scripting Defensivo y Profesional

🛡️ Directivas de Ejecución Segura

En producción, un script nunca debe continuar si un comando falla o si una variable crítica está vacía.

#!/usr/bin/env bash
# Modo estricto y seguro:
set -e          # Detiene la ejecucion si falla un comando
set -u          # Falla si se usa una variable no definida
set -o pipefail # Captura fallos dentro de pipes (|)

GREEN='\033[0;32m'
RED='\033[0;31m'
NC='\033[0m'
⚙️ Parser de Parámetros Dinámicos
#!/usr/bin/env bash
# Ejemplo: ./deploy.sh back:1.0 front:1.0
TARGET_DIR="${1:-/home/iaslab/app}"

if [ ! -d "$TARGET_DIR" ]; then
    echo -e "${RED}Error: El directorio no existe${NC}"
    exit 1
fi

echo -e "${GREEN}Desplegando en $TARGET_DIR...${NC}"
docker compose pull && docker compose up -d
Módulo 2 · Docker

Optimización de Imágenes con Multi-Stage Builds

☕ Backend (Spring Boot / Java 17)
# Etapa 1: Compilacion con Gradle/Maven
FROM eclipse-temurin:17-jdk-jammy AS builder
WORKDIR /workspace
COPY . .
RUN ./gradlew bootJar --no-daemon

# Etapa 2: Imagen ligera de produccion (JRE)
FROM eclipse-temurin:17-jre-jammy
RUN useradd -m spring
USER spring
COPY --from=builder /workspace/build/libs/*.jar app.jar
EXPOSE 9091
ENTRYPOINT ["java", "-jar", "/app.jar"]
⚛️ Frontend (React / Vite + Nginx)
# Etapa 1: Build con Node.js
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Etapa 2: Servidor Web Ultraligero Nginx
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Módulo 3 · Buenas Prácticas

Reglas de Ramas y Commits Convencionales

🌿 Mapeo de Ramas a Ambientes
  • main / master: Código de Producción. Versionado: X.Y.Z (Releases estables).
  • release/* / qa: Pruebas de integración. Versionado: X.Y.Z-RC#.
  • develop / dev: Integración continua de nuevas características. Versionado: X.Y.Z-SNAPSHOT.
  • feature/*: Desarrollo de funcionalidades individuales.
  • hotfix/*: Parches urgentes directo a producción.
✍️ Conventional Commits
  • feat: Nueva característica (e.g. feat: add user authentication).
  • fix: Corrección de un error (e.g. fix: resolve 500 error in JWT parser).
  • docs: Cambios en documentación.
  • ci: Cambios en workflows de GitHub Actions o scripts de build.
  • refactor: Reestructuración de código sin alterar comportamiento.
Módulo 4 · GitHub Actions

Anatomía de un Workflow CI/CD

📄 .github/workflows/deploy.yml
name: CI/CD Pipeline

# 1. Triggers / Eventos de Activacion
on:
  push:
    branches: [ main, docker ]
  pull_request:
    branches: [ main ]
  workflow_dispatch: # Ejecucion manual

# 2. Trabajos / Jobs
jobs:
  build-and-deploy:
    name: Build & Deploy on grid100
    runs-on: [ self-hosted, linux, x64, grid100 ]

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Execute Build
        run: docker compose build --no-cache

      - name: Deploy Containers
        run: docker compose up -d
⚡ Runners: GitHub-Hosted vs Self-Hosted
  • GitHub-Hosted: Máquinas virtuales efímeras en la nube de GitHub (Cobro por minuto, sin acceso a red interna LAN/VPN).
  • Self-Hosted (como grid100):
    • Ejecuta directamente en los servidores de la universidad.
    • Acceso a Docker nativo y bases de datos locales.
    • Conexión saliente segura por long-polling a GitHub (no requiere puertos entrantes abiertos al runner).
Módulo 4 · Despliegues Condicionales

Condicionamiento por Rama en GitHub Actions

🌿 Filtro en el Trigger (Branch Filtering)
# Archivo 1: .github/workflows/deploy-static.yml
on:
  push:
    branches:
      - main     # Solo se ejecuta en 'main'

jobs:
  deploy-static:
    runs-on: [ self-hosted ]
    steps:
      - uses: actions/checkout@v4
      - run: cp index.html /home/iaslab/app/
🐳 Despliegue en Rama Docker
# Archivo 2: .github/workflows/deploy-docker.yml
on:
  push:
    branches:
      - docker   # Solo se ejecuta en 'docker'

jobs:
  deploy-docker:
    runs-on: [ self-hosted ]
    steps:
      - uses: actions/checkout@v4
      - run: docker compose up -d --build
